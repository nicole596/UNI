#STL 
## 1. ¿Qué es?

`std::array<T, N>` es un contenedor de la STL que envuelve un arreglo de **tamaño fijo N**, conocido en **tiempo de compilación**. Está definido en `<array>`.

```cpp
#include <array>

std::array<int, 5> a{10, 20, 30, 40, 50};
```


Es un *wrapper* sobre el array de C con la interfaz de un contenedor STL (puede usar sus funciones: `size()`, `begin()`, `end()`, `at()`, etc.)

## 2. Modelo de memoria

- Los elementos se guardan en **un único bloque contiguo**.
- El objeto `std::array` **contiene** los elementos directamente: no hay puntero ni memoria dinámica.
- Si se declara como variable local, vive en la **pila (stack)**. Si es miembro de una clase, vive dentro de ella.
- `sizeof(std::array<T, N>)` es `N * sizeof(T)` (ocupa lo mismo que N `T` juntos).
- `size()` siempre es igual a la capacidad máxima: **no hay capacidad separada**.

```
Stack:  [ 10 | 20 | 30 | 40 | 50 ]
          ↑
        a.data()
```

Consecuencia: no puede crecer ni encogerse. No tiene `push_back`, `insert`, `erase`, `reserve` ni `capacity`.

## 3. Declaración e inicialización

```cpp
std::array<int, 5> a1{10, 20, 30, 40, 50};   // lista de inicialización
std::array<int, 5> a2{};                     // todos en 0 (value-initialization)
std::array<int, 5> a3;                       // valores basura
std::array<int, 5> a4{1, 2};                 // {1, 2, 0, 0, 0}: el resto en 0
std::array a5{1, 2, 3};                      // C++17: deduce <int, 3> (CTAD)
auto a6 = std::to_array({1, 2, 3});          // C++20: deduce tipo y tamaño
```

Puntos importantes:

- Sin llaves (`a3;`), los tipos primitivos **no se inicializan**, igual que un arreglo de C.
- `std::array` es un **agregado**, por eso se inicializa con llaves y no tiene constructores propios.
- N debe ser una expresión constante (`constexpr`). No puede depender de un valor leído en ejecución.

```cpp
constexpr size_t n{10};
std::array<double, n> x{};    // OK: n es constexpr

size_t m = 10;
// std::array<double, m> y;   // ERROR: m no es constante en compilación
```

## 4. Acceso a elementos

| Operación        | Descripción                       | Verifica límites                           |
| ---------------- | --------------------------------- | ------------------------------------------ |
| `a[i]`           | Acceso por índice                 | No (comportamiento indefinido si `i >= N`) |
| `a.at(i)`        | Acceso por índice                 | **Sí**, lanza `std::out_of_range`          |
| `a.front()`      | Referencia al primer elemento     | No                                         |
| `a.back()`       | Referencia al último elemento     | No                                         |
| `a.data()`       | Puntero al primer elemento (`T*`) | No                                         |
| `std::get<I>(a)` | Acceso con índice en compilación  | **Sí**, error de compilación               |

```cpp
std::array<int, 3> a{1, 2, 3};

a[1] = 20;
std::cout << a.at(2);        // 3

try {
    a.at(10);                // lanza excepción
} catch (const std::out_of_range& e) {
    std::cout << e.what();
}

std::cout << std::get<0>(a); // 1; std::get<5>(a) no compila
```

**Regla práctica:** `[]` cuando ya garantizas el índice (rápido); `at()` cuando el índice viene de fuera y quieres detectar errores.

## 5. Capacidad

|Función|Resultado|
|---|---|
|`size()`|Siempre `N`|
|`max_size()`|Siempre `N`|
|`empty()`|`true` solo si `N == 0`|

`size()` es `constexpr`, por lo que puede usarse en tiempo de compilación:

```cpp
std::array<int, 4> a{};
static_assert(a.size() == 4);
```

## 6. Iteradores

`std::array` ofrece **iteradores de acceso aleatorio** (los más potentes). Como el almacenamiento es contiguo, un iterador es en la práctica un puntero.

```cpp
std::array<int, 4> a{10, 20, 30, 40};

for (auto it = a.begin(); it != a.end(); ++it)     // normal
    *it += 5;

for (auto it = a.cbegin(); it != a.cend(); ++it)   // solo lectura
    std::cout << *it << ' ';

for (auto it = a.rbegin(); it != a.rend(); ++it)   // reverso
    std::cout << *it << ' ';

auto it = a.begin() + 2;                           // aritmética permitida
```

Los iteradores **nunca se invalidan por inserciones**, porque no existen. Solo dejan de ser válidos si el propio `std::array` se destruye.

## 7. Operaciones propias

### `fill(valor)`

Asigna el mismo valor a todos los elementos.

```cpp
std::array<int, 5> a;
a.fill(7);      // {7, 7, 7, 7, 7}
```

### `swap(otro)`

Intercambia el contenido con otro `std::array` **del mismo tipo y tamaño**. Es **O(N)**, porque hay que intercambiar elemento por elemento (a diferencia de `vector`, donde solo se intercambian punteros).

```cpp
std::array<int, 3> a{1, 2, 3}, b{4, 5, 6};
a.swap(b);      // a = {4,5,6}, b = {1,2,3}
```

### Asignación y copia

`=` copia **todos** los elementos (profunda, O(N)).

```cpp
std::array<int, 3> b = a;   // copia independiente
```

### Operadores relacionales

`==`, `!=`, `<`, `<=`, `>`, `>=` comparan **lexicográficamente**. Ambos arreglos deben ser del mismo tipo `std::array<T, N>`.

```cpp
std::array<int, 3> a{1, 2, 3}, b{1, 2, 4};
a < b;      // true
a == b;     // false
```

## 8. Complejidad

|Operación|Costo|
|---|---|
|`[]`, `at()`, `front()`, `back()`, `data()`|O(1)|
|`size()`, `empty()`|O(1) (constexpr)|
|`fill()`|O(N)|
|`swap()`|O(N)|
|Copia / asignación|O(N)|
|Comparación|O(N)|

## 9. Diferencias con el arreglo estilo C

|Aspecto|`int a[5]`|`std::array<int, 5>`|
|---|---|---|
|Conoce su tamaño|No|Sí (`size()`)|
|Se decae a puntero al pasarlo a función|**Sí** (se pierde el tamaño)|No|
|Se puede copiar con `=`|No|Sí|
|Se puede comparar con `==`|No (compara punteros)|Sí (compara elementos)|
|Iteradores|Punteros manuales|`begin()`, `end()`, etc.|
|Verificación de límites|No|Con `at()`|
|Funciona con algoritmos STL|Con `std::begin`/`std::end`|Directamente|
|Costo en tiempo de ejecución|Ninguno|Ninguno|

### Paso a funciones

```cpp
// Arreglo C: el tamaño se pierde
void f(int arr[], size_t n);

// std::array: el tamaño forma parte del tipo
void g(const std::array<int, 5>& a);

// Genérico para cualquier tamaño
template <size_t N>
void h(const std::array<int, N>& a) {
    for (auto v : a) std::cout << v << ' ';
}
```

## 10. Arreglos multidimensionales

Se anidan `std::array`. El almacenamiento total sigue siendo contiguo.

```cpp
std::array<std::array<int, 3>, 2> m{{
    {1, 2, 3},
    {4, 5, 6}
}};

m[1][2] = 60;
std::cout << m.size() << " x " << m[0].size();   // 2 x 3
```

Nota: se necesitan llaves dobles en la inicialización de arreglos anidados en muchos compiladores.

## 11. Uso con algoritmos

Al ser de acceso aleatorio, funciona con todos los algoritmos:

```cpp
#include <algorithm>
#include <numeric>

std::array<int, 6> a{5, 2, 9, 1, 7, 3};

std::ranges::sort(a);                          // {1,2,3,5,7,9}
auto it = std::ranges::find(a, 7);             // iterador al 7
int suma = std::accumulate(a.begin(), a.end(), 0);
std::ranges::reverse(a);
```

## 12. Cuándo usar `std::array`

**Úsalo cuando:**

- El tamaño se conoce en compilación y no cambia.
- Quieres evitar memoria dinámica (sistemas embebidos, código de alto rendimiento).
- Necesitas un reemplazo seguro y moderno de los arreglos de C.
- Quieres datos en la pila con buena localidad de caché.

**No lo uses cuando:**

- El tamaño se decide en ejecución (usa `std::vector`).
- El arreglo es muy grande: puede **desbordar la pila** (stack overflow). Para miles de elementos, usa `vector`.

## 13. Errores comunes

1. **No inicializar:** `std::array<int, 5> a;` contiene basura. Usa `{}`.
2. **Tamaño variable:** N tiene que ser constante en compilación.
3. **Comparar tipos distintos:** `std::array<int, 3>` y `std::array<int, 4>` son tipos diferentes; no se pueden asignar ni comparar.
4. **Bucles con `int` e `size()`:** `size()` devuelve `size_t` (sin signo). Usa `size_t i` para evitar advertencias de comparación.
5. **Usar `[]` fuera de rango:** compila y ejecuta, pero es comportamiento indefinido.
6. **Arreglos enormes en la pila:** pueden provocar _stack overflow_.

## 14. Resumen

- Tamaño **fijo**, definido en compilación.
- Memoria **contigua**, sin heap.
- Sin sobrecarga frente al arreglo de C.
- Interfaz de contenedor completa de solo lectura/modificación de elementos, pero **sin** inserción ni borrado.
- Iteradores de **acceso aleatorio**.
- `swap` es O(N).
