#STL 
## 1. Qué es

`std::list<T>` es una **lista doblemente enlazada**: cada elemento vive en un **nodo independiente** que guarda el valor y dos punteros, uno al nodo anterior y otro al siguiente. Está definida en `<list>`.

```cpp
#include <list>

std::list<int> l{10, 20, 30, 40, 50};
```

Su fortaleza es insertar y borrar **en cualquier posición en O(1)** (si ya tienes un iterador ahí), sin mover otros elementos y sin invalidar iteradores.

## 2. Modelo interno

```
  nullptr ← [prev|10|next] ⇄ [prev|20|next] ⇄ [prev|30|next] ⇄ [prev|40|next] → nullptr
              ▲                                                    ▲
            head                                                 tail
```

- Cada nodo se reserva por separado en el heap (`new` interno, vía el _allocator_).
- Los nodos están **dispersos** en memoria.
- La lista mantiene punteros al primer y último nodo, y normalmente un contador de tamaño.
- En muchas implementaciones hay un **nodo centinela** que representa `end()`.

Costo de memoria por elemento: `sizeof(T)` + **2 punteros** (16 bytes en 64 bits) + sobrecarga del asignador. Para tipos pequeños (`int`), la sobrecarga es mayor que el dato.

## 3. Construcción e inicialización

```cpp
std::list<int> l1;                          // vacía
std::list<int> l2{10, 20, 30};              // lista de inicialización
std::list<int> l3(5);                       // 5 elementos en 0
std::list<int> l4(5, 7);                    // 5 elementos en 7
std::list<int> l5(l2);                      // copia
std::list<int> l6(l2.begin(), l2.end());    // desde un rango
```

## 4. Lo que NO tiene

|Ausente|Motivo|
|---|---|
|`operator[]` y `at()`|No hay acceso aleatorio: llegar al elemento _k_ requiere recorrer k nodos|
|`data()`|No hay memoria contigua|
|`capacity()` / `reserve()`|Cada nodo se reserva por separado|
|`std::sort` compatible|`std::sort` exige iteradores de acceso aleatorio; `list` tiene su propio `sort()`|

## 5. Interfaz

### Acceso

|Operación|Descripción|Costo|
|---|---|---|
|`front()`|Primer elemento|O(1)|
|`back()`|Último elemento|O(1)|
|`size()`|Cantidad de elementos|O(1) (desde C++11)|
|`empty()`|¿Está vacía?|O(1)|

### Modificadores generales

|Operación|Descripción|Costo|
|---|---|---|
|`push_front(x)` / `emplace_front(...)`|Agrega al inicio|O(1)|
|`push_back(x)` / `emplace_back(...)`|Agrega al final|O(1)|
|`pop_front()` / `pop_back()`|Quita del inicio / final|O(1)|
|`insert(pos, ...)`|Inserta antes de `pos`|O(1) por elemento|
|`erase(pos)` / `erase(a, b)`|Borra elementos|O(1) por elemento|
|`clear()`|Vacía la lista|O(n)|
|`resize(n)`|Cambia la cantidad de elementos|O(n)|
|`swap(otra)`|Intercambia contenido|O(1)|
|`assign(...)`|Reemplaza el contenido|O(n)|

```cpp
std::list<int> l{20, 30, 40, 50, 60, 70, 80};
l.push_front(10);
l.push_back(90);

auto it = l.begin();
std::advance(it, l.size() / 2);      // O(n): recorre nodo por nodo

std::array<int, 3> mas{-40, -50, -60};
l.insert(it, mas.begin(), mas.end());   // inserta antes de 'it', O(3)
```

## 6. Iteradores

Los iteradores de `list` son **bidireccionales**: permiten `++` y `--`, pero **no** aritmética (`it + 5` no compila).

```cpp
auto it = l.begin();
// it + 3;                 // ERROR
std::advance(it, 3);       // avanza 3 nodos: O(3)
auto it2 = std::next(it, 2);   // copia avanzada 2 posiciones
auto it3 = std::prev(it);      // copia retrocedida 1 posición
auto d   = std::distance(l.begin(), it);   // O(n): cuenta nodos
```

Variantes: `begin/end`, `cbegin/cend` (solo lectura), `rbegin/rend` (reverso).

### Invalidación (la gran ventaja)

|Operación|Efecto|
|---|---|
|`insert`, `push_*`, `emplace_*`|**Ningún** iterador, puntero o referencia se invalida|
|`erase`, `pop_*`, `remove`|Solo se invalidan los del elemento borrado|
|`splice`|Los iteradores siguen válidos, pero ahora pertenecen a la lista destino|
|`swap`|Siguen válidos, pero apuntan al otro contenedor|

```cpp
std::list<int> l{1, 2, 3};
auto it = l.begin();         // apunta al 1
l.push_back(4);
l.push_front(0);
std::cout << *it;            // válido: 1
```

### Borrar mientras se recorre

```cpp
for (auto it = l.begin(); it != l.end(); ) {
    if (*it % 2 == 0) it = l.erase(it);   // erase devuelve el siguiente
    else ++it;
}
```

## 7. Operaciones propias de `list`

Estas funciones aprovechan los enlaces para trabajar **sin copiar ni mover elementos**.

### `remove(valor)` y `remove_if(predicado)`

Borran directamente (no requieren el idioma erase-remove). Desde C++20 devuelven la cantidad de elementos borrados.

```cpp
l.remove(40);                                   // borra todos los 40
auto pred = [](int x) { return x % 60 == 0; };
l.remove_if(pred);                              // borra los que cumplen la condición
```

### `splice(pos, otra, ...)`: mover nodos

Transfiere nodos de otra lista **relinkeando punteros**. No copia ni construye elementos.

```cpp
std::list<std::string> l1{"Ene", "Feb", "Mar", "Abr", "Sep", "Oct", "Nov", "Dic"};
std::list<std::string> l2{"May", "Jun", "Jul", "Ago"};

auto pos = l1.begin();
std::advance(pos, 4);               // apunta a "Sep"

l1.splice(pos, l2);                 // mueve TODO l2 antes de "Sep"
// l1: Ene Feb Mar Abr May Jun Jul Ago Sep Oct Nov Dic
// l2: (vacía)
```

Tres formas:

|Forma|Descripción|
|---|---|
|`splice(pos, otra)`|Mueve toda la lista `otra`|
|`splice(pos, otra, it)`|Mueve un solo elemento|
|`splice(pos, otra, a, b)`|Mueve el rango `[a, b)`|

Costo: O(1) para elemento único o lista completa; O(k) para un rango (en algunas implementaciones, por actualizar el contador de tamaño). Los iteradores a los elementos movidos **siguen siendo válidos**.

### `sort()` y `sort(comp)`

Ordena la lista por **re-enlazado de nodos** (merge sort). Es **O(n log n)** y estable. No invalida iteradores.

```cpp
l1.sort();                          // ascendente
l1.sort(std::greater<>());          // descendente
```

### `merge(otra)`

Combina dos listas **ya ordenadas** en una sola ordenada y **deja vacía la otra**. Es O(n + m) y estable.

```cpp
l1.sort();
l2.sort();
l1.merge(l2);        // l1 queda ordenada con todo; l2 vacía
```

Si las listas no están ordenadas antes, el resultado es incorrecto (comportamiento indefinido en algunos casos).

### `reverse()`

Invierte el orden de los nodos. O(n), sin copiar elementos.

### `unique()`

Elimina elementos **consecutivos** repetidos (normalmente se usa tras `sort()`).

```cpp
std::list<int> l{1, 1, 2, 2, 2, 3, 1};
l.unique();          // {1, 2, 3, 1}  (solo colapsa vecinos iguales)
```

### `emplace_front` / `emplace_back` / `emplace`

Construyen el elemento directamente en el nodo, evitando copias temporales.

```cpp
std::list<std::string> paises;
paises.emplace_back("Peru");
paises.emplace_front("Chile");
```

## 8. Recorrido en paralelo con iteradores

Al no tener `[]`, se usan iteradores. Cuidado con no desbordar la longitud de una de las listas.

```cpp
std::list<int> a{10, 20, 30}, b{-1, -2, -3}, c(a.size());

auto ia = a.cbegin();
auto ib = b.cbegin();
auto ic = c.begin();
for (; ia != a.cend(); ++ia, ++ib, ++ic)
    *ic = *ia + *ib;                // c = {9, 18, 27}
```

Es buena práctica comprobar antes que los tamaños coincidan.

## 9. Complejidad

|Operación|Costo|
|---|---|
|`front()`, `back()`, `size()`, `empty()`|O(1)|
|`push_*`, `pop_*`|O(1)|
|`insert` / `erase` con iterador|O(1)|
|Llegar a la posición _k_ (`advance`, `next`)|O(k)|
|Búsqueda (`find`)|O(n)|
|`remove`, `remove_if`, `unique`, `reverse`|O(n)|
|`sort`|O(n log n)|
|`merge`|O(n + m)|
|`splice` (lista completa o un elemento)|O(1)|
|`swap`|O(1)|
|`clear`|O(n)|

## 10. Rendimiento real: la advertencia

Aunque `list` gana en teoría para inserciones en medio, en la práctica suele ser **más lenta** que `vector` en muchos escenarios:

- **Mala localidad de caché**: los nodos están dispersos, cada salto puede ser un _cache miss_.
- **Asignaciones frecuentes**: cada inserción reserva un nodo en el heap.
- **Sobrecarga de memoria**: 2 punteros por elemento.
- Llegar a la posición donde insertar ya cuesta O(n), lo que **anula** la ventaja de la inserción O(1) si no tienes el iterador de antemano.

Regla: mide antes de elegir `list` por rendimiento. Elígela cuando necesites sus **garantías** (iteradores estables, `splice`), no solo velocidad.

## 11. Variante: `std::forward_list`

Lista **simplemente enlazada** (un solo puntero por nodo): menos memoria, solo recorre hacia adelante.

|Aspecto|`list`|`forward_list`|
|---|---|---|
|Enlaces por nodo|2|1|
|Iteradores|Bidireccionales|Solo hacia adelante|
|`size()`|Sí|No|
|`push_back` / `back()`|Sí|No|
|Inserción|`insert` (antes de `pos`)|`insert_after` (después de `pos`)|

## 12. Comparación con `vector` y `deque`

|Aspecto|`vector`|`deque`|`list`|
|---|---|---|---|
|Acceso por índice|O(1)|O(1)|No|
|Insertar al inicio|O(n)|O(1)|O(1)|
|Insertar al final|O(1) amortizado|O(1)|O(1)|
|Insertar en el medio|O(n)|O(n)|O(1) con iterador|
|Memoria contigua|Sí|No|No|
|Sobrecarga por elemento|Ninguna|Baja|2 punteros + asignación|
|Iteradores estables|No|No|**Sí**|
|`sort`|`std::sort`|`std::sort`|`list::sort()`|
|`splice`|No|No|**Sí**|
|Localidad de caché|Excelente|Buena|Mala|

## 13. Cuándo usar `list`

**Úsala cuando:**

- Insertas o borras mucho **en medio** y ya tienes los iteradores.
- Necesitas que los **iteradores y referencias sigan válidos** pese a modificaciones.
- Quieres **mover bloques** de elementos entre listas sin copiar (`splice`).
- Los elementos son costosos de copiar o mover y no puedes moverlos de lugar.
- Mantienes estructuras tipo LRU cache (con `splice` para reordenar en O(1)).

**Evítala cuando:**

- Necesitas acceso por índice.
- Haces recorridos frecuentes de grandes volúmenes (usa `vector`).
- Los elementos son pequeños (la sobrecarga domina).
- Solo agregas y quitas en los extremos (usa `deque` o `vector`).

## 14. Errores comunes

1. Intentar `l[i]` o `l.at(i)`: no existen.
2. Usar `it + n` en lugar de `std::advance(it, n)`.
3. Llamar `std::sort(l.begin(), l.end())` en vez de `l.sort()`.
4. Usar `merge` con listas sin ordenar.
5. Usar un iterador después de `erase` sin tomar el valor devuelto.
6. Suponer que `unique()` elimina duplicados no consecutivos (necesita `sort()` antes).
7. Esperar que `splice` copie: **mueve**, y deja la lista origen modificada o vacía.
8. Llamar `front()`, `back()`, `pop_front()` o `pop_back()` sobre una lista vacía.
9. Elegir `list` por "inserción O(1)" ignorando el costo de llegar a la posición.

## 15. Resumen

- **Lista doblemente enlazada**: un nodo por elemento con punteros `prev` y `next`.
- Inserción y borrado en **O(1)** con iterador; **sin acceso por índice**.
- Iteradores **bidireccionales**; usar `std::advance` / `std::next`.
- Iteradores y referencias **estables** ante inserciones y borrados ajenos.
- Métodos propios: `remove`, `remove_if`, `splice`, `sort`, `merge`, `reverse`, `unique`.
- Mayor consumo de memoria y peor localidad de caché que `vector` y `deque`.
