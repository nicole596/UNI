#STL 

## 1. Qué es

`std::vector<T>` es un **arreglo dinámico**: un contenedor secuencial cuyo tamaño puede cambiar en tiempo de ejecución, con elementos almacenados en **memoria contigua**. Está definido en `<vector>`.

Es el contenedor **por defecto** en C++: si no tienes una razón concreta para otro, usa `vector`.

```cpp
#include <vector>

std::vector<int> v{10, 20, 30, 40, 50};
```

## 2. Modelo interno

Un `vector` es, conceptualmente, un objeto pequeño en la pila que administra un bloque en el **heap**:

```
Objeto vector (stack)             Bloque en el heap
┌──────────────────┐            ┌────┬────┬────┬────┬────┬────┬────┬────┐
│ begin  ──────────┼──────────► │ 10 │ 20 │ 30 │ 40 │ 50 │ ?  │ ?  │ ?  │
│ end    ──────────┼──────┐     └────┴────┴────┴────┴────┴────┴────┴────┘
│ end_of_storage ──┼───┐  │                            ▲              ▲
└──────────────────┘   │  └────────────────────────────┘              │
                       └──────────────────────────────────────────────┘
   size()     = end - begin             (elementos construidos)
   capacity() = end_of_storage - begin  (espacio reservado)
```

Dos conceptos distintos:

|Concepto|Significado|
|---|---|
|**`size()`**|Cantidad de elementos que hay actualmente|
|**`capacity()`**|Cantidad de elementos que caben sin reasignar memoria|

Siempre se cumple `size() <= capacity()`.

## 3. Construcción e inicialización

```cpp
std::vector<int> v1;                    // vacío
std::vector<int> v2{10, 20, 30};        // lista de inicialización
std::vector<int> v3(5);                 // 5 elementos, todos en 0
std::vector<int> v4(5, 7);              // 5 elementos, todos en 7
std::vector<int> v5(v2);                // copia de v2
std::vector<int> v6(v2.begin(), v2.end()); // desde un rango de iteradores
std::vector<int> v7(std::move(v2));     // movimiento: v2 queda vacío
```

### Trampa: paréntesis vs llaves

```cpp
std::vector<int> a(5);      // 5 elementos con valor 0:  {0, 0, 0, 0, 0}
std::vector<int> b{5};      // 1 elemento con valor 5:   {5}
std::vector<int> c(5, 7);   // {7, 7, 7, 7, 7}
std::vector<int> d{5, 7};   // 2 elementos:              {5, 7}
```

Las llaves **prefieren** el constructor de lista de inicialización. Con paréntesis se usa el constructor de tamaño. Por eso `std::vector<unsigned long long> v6{v4.size()}` crea **un solo elemento** con el valor `v4.size()`, no un vector de ese tamaño.

## 4. Acceso a elementos

| Operación   | Descripción                | Verifica límites                             |
| ----------- | -------------------------- | -------------------------------------------- |
| `v[i]`      | Acceso por índice          | No                                           |
| `v.at(i)`   | Acceso por índice          | **Sí** (`std::out_of_range`)                 |
| `v.front()` | Primer elemento            | No (comportamiento indefinido si está vacío) |
| `v.back()`  | Último elemento            | No (comportamiento indefinido si está vacío) |
| `v.data()`  | Puntero al bloque contiguo | No                                           |

`data()` permite pasar el vector a APIs de C:

```cpp
void procesar(const int* arr, size_t n);
procesar(v.data(), v.size());
```

## 5. Capacidad y gestión de memoria

|Función|Efecto|
|---|---|
|`size()`|Número de elementos|
|`capacity()`|Espacio reservado|
|`empty()`|`true` si `size() == 0`|
|`reserve(n)`|Asegura capacidad ≥ n (no cambia `size`)|
|`resize(n)`|Cambia `size` a n (crea o destruye elementos)|
|`shrink_to_fit()`|Solicita reducir `capacity` hasta `size` (no vinculante)|
|`clear()`|Elimina todos los elementos (`size = 0`), **mantiene la capacidad**|

### `reserve` vs `resize`

```cpp
std::vector<int> v;
v.reserve(100);   // size = 0,   capacity >= 100  (no hay elementos)
v.resize(10);     // size = 10,  los 10 elementos valen 0
```

- `reserve` prepara memoria: **no** crea elementos y no es válido hacer `v[0]` tras él.
- `resize` cambia la cantidad de elementos reales.

### Estrategia de crecimiento

Cuando `push_back` encuentra `size == capacity`, el vector:

1. Reserva un bloque nuevo, **más grande** (factor geométrico).
2. **Mueve o copia** todos los elementos al bloque nuevo.
3. Libera el bloque viejo.

El factor de crecimiento depende de la implementación: normalmente **2×** en GCC y Clang, **1.5×** en MSVC.

```cpp
std::vector<int> v;
size_t cap = v.capacity();
for (int i = 0; i < 20; ++i) {
    v.push_back(i);
    if (v.capacity() != cap) {
        cap = v.capacity();
        std::cout << "size=" << v.size() << " capacity=" << cap << '\n';
    }
}
// GCC imprime capacidades 1, 2, 4, 8, 16, 32
```

### Análisis amortizado

Cada reasignación cuesta O(n), pero ocurre cada vez menos seguido (la capacidad se duplica). Repartiendo el costo entre todas las inserciones, `push_back` es **O(1) amortizado**.

**Consejo:** si conoces el tamaño final, llama a `reserve(n)` primero. Evitas reasignaciones intermedias.

## 6. Modificadores

### Agregar al final

```cpp
v.push_back(42);        // copia o mueve un objeto ya construido
v.emplace_back(42);     // construye el elemento directamente en el vector
```

`emplace_back` pasa los argumentos al constructor del tipo, evitando una copia temporal:

```cpp
std::vector<std::string> nombres;
nombres.push_back("Ana");          // crea un string temporal y lo mueve
nombres.emplace_back("Luis");      // construye el string directamente
```

### Quitar del final

```cpp
v.pop_back();           // elimina el último (UB si está vacío); no devuelve nada
```

### Insertar en una posición

```cpp
v.insert(v.begin() + 2, 99);                        // un elemento
v.insert(v.begin() + 2, 3, 0);                      // tres ceros
v.insert(v.begin() + 2, a.begin(), a.end());        // un rango (como en tu vector_example_2)
v.insert(v.end(), otro.begin(), otro.end());        // concatenar al final
v.emplace(v.begin() + 1, args...);                  // construir en el lugar
```

Insertar en el medio **desplaza** los elementos posteriores: **O(n)**.

### Borrar

```cpp
v.erase(v.begin() + 3);                  // un elemento
v.erase(v.begin(), v.begin() + 5);       // rango [primero, último)
v.clear();                               // todos
```

Borrar en el medio también desplaza elementos: **O(n)**.

## 7. Idioma erase-remove

Para eliminar **todos los elementos con cierto valor o condición**:

```cpp
// Estilo clásico (C++11/17)
v.erase(std::remove(v.begin(), v.end(), -1.0), v.end());

// Con rangos (C++20): remove devuelve un subrango con los "residuales"
auto residuales = std::ranges::remove(v, -1.0);
v.erase(residuales.begin(), v.end());

// C++20: función libre que hace todo y devuelve cuántos borró
auto n = std::erase(v, -1.0);
auto m = std::erase_if(v, [](double x) { return x < 0; });
```

Por qué dos pasos: `remove` **no cambia el tamaño** del vector. Solo mueve los elementos que se conservan hacia el inicio y deja basura al final. Es `erase` quien reduce `size`.

```
Antes:   10 20 -1 30 40 -1 50
remove:  10 20 30 40 50 ?  ?        ← size sigue siendo 7
erase:   10 20 30 40 50             ← size = 5
```

## 8. Iteradores

Los iteradores de `vector` son de **acceso aleatorio** y contiguos (en la práctica, punteros).

```cpp
for (auto it = v.begin(); it != v.end(); ++it) *it *= 2;
for (auto it = v.rbegin(); it != v.rend(); ++it) std::cout << *it;
auto mitad = v.begin() + v.size() / 2;
```

### Reglas de invalidación

Esta es una de las fuentes de error más frecuentes.

|Operación|Efecto sobre iteradores, punteros y referencias|
|---|---|
|`push_back` / `emplace_back`|Si hay **reasignación**: todos se invalidan. Si no: solo se invalida `end()`|
|`insert` / `emplace`|Si hay reasignación: todos. Si no: los de la posición de inserción en adelante|
|`erase`|Los de la posición borrada en adelante (incluido `end()`)|
|`pop_back`|Solo el último elemento y `end()`|
|`reserve`|Todos, si realmente cambia la capacidad|
|`clear`|Todos|
|`shrink_to_fit`|Posiblemente todos|
|`swap`|Siguen válidos pero apuntan al otro contenedor|

```cpp
std::vector<int> v{1, 2, 3};
int& r = v[0];
v.push_back(4);      // puede reasignar
// r ya puede ser inválida → comportamiento indefinido
```

### Borrar mientras se recorre

```cpp
// MAL: it queda inválido tras erase
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it < 0) v.erase(it);

// BIEN: erase devuelve el siguiente iterador válido
for (auto it = v.begin(); it != v.end(); ) {
    if (*it < 0) it = v.erase(it);
    else ++it;
}

// MEJOR: std::erase_if (C++20)
std::erase_if(v, [](int x) { return x < 0; });
```

## 9. Operaciones con otros contenedores y algoritmos

```cpp
std::ranges::copy(origen, std::back_inserter(v));   // agrega al final
std::ranges::sort(v);                               // ordena
auto it = std::ranges::find(v, "Mars");             // busca
bool igual = (v1 == v2);                            // comparación lexicográfica
v1.swap(v2);                                        // O(1): intercambia punteros internos
v1 = v2;                                            // copia (O(n))
v1 = std::move(v2);                                 // movimiento (O(1))
v.assign(5, 0);                                     // reemplaza contenido
```

`swap` es **O(1)** porque solo se intercambian los tres punteros internos, no los elementos.

## 10. Semántica de movimiento

Al reasignar, el vector **mueve** los elementos al bloque nuevo si el constructor de movimiento del tipo es `noexcept`. Si no lo es (y el tipo es copiable), usa **copia** para mantener la garantía de excepciones.

Consejo: marca `noexcept` los constructores de movimiento de tus clases para que `vector` pueda moverlas en reasignaciones.

## 11. Complejidad

|Operación|Costo|
|---|---|
|`[]`, `at()`, `front()`, `back()`, `data()`|O(1)|
|`push_back` / `emplace_back`|O(1) amortizado|
|`pop_back`|O(1)|
|`insert` / `erase` al final|O(1)|
|`insert` / `erase` al inicio o en el medio|O(n)|
|`clear`|O(n) (destruye elementos)|
|`reserve(n)`|O(n) si reasigna|
|`swap`|O(1)|
|Búsqueda lineal (`find`)|O(n)|
|Búsqueda binaria (ordenado)|O(log n)|

## 12. Caso especial: `std::vector<bool>`

`vector<bool>` es una **especialización** que empaqueta los bits (1 bit por elemento) para ahorrar memoria. Por eso:

- `v[i]` no devuelve `bool&` sino un **proxy** (`std::vector<bool>::reference`).
- `data()` no existe.
- No es un contenedor "normal" y rompe código genérico.

Si necesitas un arreglo de booleanos común, usa `std::vector<char>`, `std::vector<uint8_t>` o `std::deque<bool>`.

## 13. Cuándo usar `vector`

**Úsalo cuando:**

- Necesitas una colección que crece y se recorre con frecuencia.
- Quieres acceso por índice rápido.
- La mayoría de las inserciones son al final.
- Necesitas compatibilidad con APIs de C (`data()`).
- Buscas la mejor localidad de caché posible.

**Considera otro contenedor cuando:**

- Insertas o borras mucho al inicio → `std::deque`.
- Necesitas iteradores estables con muchas inserciones en medio → `std::list`.
- El tamaño es fijo y conocido → `std::array`.

## 14. Errores comunes

1. Confundir `v(5)` con `v{5}`.
2. Usar `v[i]` sin comprobar que `i < size()`.
3. Guardar iteradores o referencias y luego hacer `push_back`.
4. Llamar `remove` sin `erase` y creer que el vector se encogió.
5. Usar `reserve` y luego acceder con `[]` creyendo que ya hay elementos.
6. Comparar `int i` con `size()` (tipo sin signo).
7. Hacer `pop_back()` o `back()` sobre un vector vacío.
8. Insertar al inicio en un bucle largo (O(n²) acumulado).

## 15. Resumen

- Arreglo dinámico en el **heap**, memoria **contigua**.
- `size` ≠ `capacity`; crece geométricamente.
- `push_back` es O(1) amortizado; insertar/borrar en medio es O(n).
- Iteradores de acceso aleatorio, **frágiles** ante reasignaciones.
- `erase` + `remove` (o `std::erase`) para filtrar elementos.
- Es la **opción por defecto** de la STL.
